🎯 Guiding Principles

1. One dominant technical objective at a time

I will not run multiple full technical curricula simultaneously.

Other interests are documented and placed into the appropriate future phase.

2. Competency gates decide progress

The calendar is a planning tool.

I move forward when I can demonstrate ability, not simply because a certain number of months has passed.

3. University remains protected

My degree is part of the plan.

Technical development must not destroy academic performance.

4. Build before claiming

I want evidence of ability:

«Learn → Build → Test → Document → Demonstrate»

5. Communication develops continuously

Public speaking and technical explanation remain a small weekly habit rather than another full curriculum.

6. New ideas go to the Parking Lot

A new idea does not automatically become this week's project.

It gets recorded, reviewed later, and promoted only when the roadmap says it is appropriate.
